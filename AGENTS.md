# LearnWithRico course app

The paid course app for LearnWithRico. `frontend/` is the whole runtime: a Next.js 16 app
on Vercel with Neon Postgres (Drizzle), Better Auth, Stripe Checkout and SES email.

`backend/` (Express on Lambda + DynamoDB + Cognito) is **legacy**. It is being retired;
do not add to it and do not call it from `frontend/`.

Current feature work: `specs/paid_checkout/design.md` (issue #31).

**External systems** (Vercel, Neon, Stripe, AWS, Google OAuth, Mux, GitHub): read
`.claude/skills/external-systems/SKILL.md` before inspecting or changing any of them. It has the resource IDs
per environment, how to connect (CLI or MCP), where credentials live, and the local → preview → production
promotion steps. Every external change needs the owner's approval.

## Layout (frontend/)

```
app/         transport only: pages, server actions, route handlers. No SQL, no business rules.
features/    one folder per business feature (purchases, accounts, enrollment, courses,
             progress, students, feedback). Each exposes its public API through index.ts;
             other code imports only that index. A feature touches only its own tables.
platform/    plumbing with no business rules: db (Drizzle client, migrations, seed), stripe, email.
e2e/         Playwright specs.
```

## Setup

```bash
cd frontend
nvm use                # Node 22 (.nvmrc)
pnpm install
# .env.local       → DATABASE_URL for the Neon "dev" branch (+ other secrets)
# .env.test.local  → DATABASE_URL for the Neon "test" branch (reset by every test run)
pnpm db:migrate && pnpm db:seed
pnpm dev               # http://localhost:3000
```

Neon projects live in the Vercel-managed org: `learnwithrico-production` (Vercel Production)
and `learnwithrico-preview` (Vercel Preview, with `dev` and `test` branches).

## Database

- Schema lives with its feature: `features/<name>/<name>.schema.ts`, gathered in `platform/db/schema.ts`.
- `features/accounts/accounts.schema.ts` is generated by `npx auth@latest generate` — regenerate, don't hand-edit.
- Change schema → `pnpm db:generate --name <change>` → commit the SQL in `platform/db/migrations/`.
- The seed is idempotent; a fresh database must build from migrations + seed alone.

## Verification — nothing is done until it is proven

`pnpm verify` runs everything below. Run it before every commit and report its real output.

| Layer | Command | Proves |
|---|---|---|
| Types | `pnpm typecheck` | |
| Lint | `pnpm lint` | |
| Build | `pnpm build:check` | the production build (prerendering, Suspense/dynamic rules) into `.next-build` |
| Service tests | `pnpm test` (Vitest) | business rules against **real Postgres** (Neon `test` branch, dropped, migrated and seeded per run) |
| End-to-end | `pnpm test:e2e` (Playwright) | the real app in a real browser; Playwright starts its own dev server on :3100 wired to the `test` branch |

- Put service tests next to the code (`*.test.ts`); test through a feature's `index.ts`.
- Prefer real dependencies over mocks. Mock only what can't run locally.
- Never weaken a check to make it pass (`@ts-ignore`, `eslint-disable`, `as any`, `.skip`).
- Things automation can't prove (real Google sign-in, real inbox delivery) go in a manual checklist.

## Conventions

- pnpm 10, TypeScript, ES modules.
- Route handlers wrap their body in `handle()` (`platform/http.ts`), which rethrows Next.js control flow
  (`unstable_rethrow`) before mapping service errors — never catch-and-swallow in transport code.
- Client components import Better Auth only via `features/accounts/auth-client.ts` / `use-sign-out.ts`
  (the feature's `index.ts` is server-only).
- Errors from services: `UnauthorizedError` / `ForbiddenError` / `NotFoundError` (`platform/errors.ts`); transport maps them to redirects or 401/403/404.
- Never cache user-specific authorization data (`'use cache'`, SWR across users, cookie caches).
